🎨Herramienta destacada · Claude Design Research preview Incluido en el plan Teams de H&A

Claude Design es el producto de Anthropic Labs (lanzado el 17 de abril de 2026) para generar prototipos visuales, presentaciones, one-pagers y mockups conversando con Claude. Corre sobre Opus 4.7. A diferencia de un artifact suelto, es un espacio de diseño completo: iterás la parte visual en lenguaje natural y después la exportás o se la pasás a Claude Code para el HTML final.

📥 Entrada de datos real
Prompt de texto, imágenes, documentos DOCX/PPTX/XLSX, una URL para "capturar" el diseño de un sitio, o un repositorio de código completo.
🎯 Hereda tu marca
Si le mostrás tu código o archivos existentes, arma un sistema de diseño (colores, tipografía, componentes) y lo aplica a los proyectos siguientes.
📤 Exporta a
PDF, PowerPoint y HTML, más conectores directos a Canva, Adobe Express, Miro, Wix, Replit y Vercel, entre otros.
⚙️ Solo front-end
Genera interfaz visual (HTML/CSS/JS). No arma bases de datos ni lógica de servidor — eso queda para Claude Code.
🔗 Se integra con Claude Code
Con /design-sync importás el sistema de diseño a Claude Code, y con /design trabajás Claude Design desde la terminal o la app de Code. Cuando el diseño está listo, se lo "entregás" a Claude Code para que lo convierta en el HTML final del repo.
Cuándo usarlo en Payroll
🧾Armar el mockup de un nuevo formato de recibo antes de pedirle a Claude Code que lo programe.
📊Preparar un one-pager o deck para presentar un cambio de proceso a un cliente.

Esta sección es para quien mantiene o edita el código de este portal (IT / desarrollo). Si solo necesitás usar Claude para tu trabajo diario, quedate en "Por tarea" o "Por visualización".

Claude Code es la versión de Claude para trabajar directamente sobre este repositorio de GitHub: lee y edita los archivos HTML del portal (como esta misma guía, el Gestor de Novedades o el análisis de IG anual), ejecuta comandos, prueba los cambios y prepara los commits. No es un chat aparte — trabaja sobre el código real que después queda publicado.

La diferencia con usar Claude por chat normal es que Claude Code ve todo el repositorio: puede abrir varios archivos a la vez, mantener el mismo estilo visual entre páginas y correr el resultado antes de mostrártelo. Sirve tanto para pedirle una página nueva como para mantener las que ya existen.

Primeros pasos en la app de escritorio (para quien nunca lo usó)
1
Abrí la app de escritorio de Claude y andá a la pestaña Code (arriba, al centro). Si pide upgrade de plan, avisale a IT — con el plan Teams de H&A ya debería estar habilitado.
2
Elegí el entorno. Para trabajar sobre tus propios archivos elegí Local. En Windows hace falta tener Git instalado para que funcione; en Mac ya viene instalado.
3
Seleccioná la carpeta del proyecto con "Select folder". Clave para entender: Claude Code solo ve y puede modificar lo que está dentro de esa carpeta — no accede a nada afuera. Por eso conviene:
📁Tener una carpeta por proyecto (una para el repo de la guía de Payroll, otra para el Validador de Novedades), no todo mezclado.
📁Elegir la carpeta raíz del repositorio clonado de GitHub, no una subcarpeta suelta, así Claude ve todos los archivos relacionados (HTML, imágenes, etc.).
4
Elegí el modelo en el desplegable junto al botón de enviar (ver "Qué modelo usar en Claude Code" más abajo).
5
Escribí el pedido en el chat, igual que en Claude normal (ej: "agregá una tarjeta nueva en la sección Por visualización explicando Claude Design").
6
Revisá los cambios antes de aceptarlos. Cuando Claude edita un archivo aparece un indicador tipo +12 −1. Hacé clic para ver el diff línea por línea y comentar si algo no está bien — Claude ajusta con tu comentario.
7
Elegí cuánto control querés tener (modo de permisos):
Ask permissions (default): aprobás cada cambio antes de que se aplique. Recomendado para principiantes.
Auto accept edits: más rápido, pero Claude aplica los cambios sin pedir aprobación previa.
Plan mode: Claude arma un plan sin tocar ningún archivo todavía — útil antes de un cambio grande.
8
Previsualizá el resultado con el botón "Preview" antes de dar por terminado el cambio, si es una página HTML.
⚠️ Antes de publicar para que otros lo vean
Claude Code puede preparar el commit e incluso abrir un pull request en GitHub, pero la publicación final la maneja {{ reviewerName }}. Si terminaste un cambio y necesitás que quede visible para el resto del equipo (por ejemplo, que se actualice la guía compartida), no lo subas directo — avisale a {{ reviewerName }} con un resumen breve de qué cambiaste y por qué, para que lo revise y lo suba a GitHub. Esto evita que cambios sin revisar queden publicados por error.
Qué modelo usar en Claude Code
Haiku 4.5 $1 / $5 por MTok
Subagentes rápidos
Claude Code lo usa por detrás para tareas chicas y en paralelo — buscar dónde está definida una función, listar archivos, chequeos simples. No conviene pedirlo como modelo principal para escribir código de producción.
Sonnet 5 $3 / $15 por MTok
Default para programar
El que usás para el día a día: agregar un campo al recibo, corregir un bug puntual, ajustar estilos de una página existente. Casi el nivel de Opus en tareas de código a un costo mucho menor — arrancá siempre por acá.
Opus 4.8 $5 / $25 por MTok
Cambios grandes o riesgosos
Para refactors que tocan varios archivos, lógica de cálculo compleja (SAC, retenciones, recálculos) o cuando necesitás que verifique su propio trabajo antes de entregar. Más lento y caro que Sonnet, pero más confiable en tareas largas.
Fable 5 $10 / $50 por MTok
Último recurso
Pensado para tareas de código de máxima complejidad y largo aliento — migrar todo un sistema, auditar el repositorio completo o trabajar de forma autónoma por varios minutos sin supervisión. Es el más caro: usalo solo cuando Opus no alcanza.

Razonamiento extendido y niveles de esfuerzo
Son dos configuraciones separadas que se pueden combinar, disponibles tanto en el chat normal como en Claude Code.
🧠 Razonamiento extendido ("thinking")
Claude piensa paso a paso antes de responder, mostrando ese razonamiento en una sección aparte. Sirve para problemas con varios pasos lógicos encadenados.
⚡ Esfuerzo ("effort")
Controla qué tan a fondo trabaja Claude en general (razonamiento + cantidad de pasos y herramientas), no solo si piensa o no. Se elige junto al selector de modelo, al lado del botón de enviar.
Low
Tareas simples, búsquedas rápidas, alto volumen — priorizás velocidad.
Estira más tu límite de uso.
Medium
Tareas rutinarias donde no hace falta el máximo nivel de detalle.
Buen balance costo / calidad.
High ★
(Default) Razonamiento complejo, código, tareas con varios pasos — el mejor balance general.
Es el nivel por defecto de Sonnet 5.
Extra high
Tareas de código o agénticas largas y difíciles.
Disponible desde Opus 4.7 en adelante (xhigh).
Max
Cuando necesitás el máximo posible de profundidad de análisis, sin importar el tiempo o el costo.
La opción más lenta y cara.
Ejemplo aplicado — fórmulas encadenadas
Para interpretar fórmulas M4 que encadenan varios conceptos (por ejemplo algo que combina #3510, #4050 y #9080), conviene High o Max + thinking activado, porque hay que rastrear dependencias entre conceptos. Para consultas simples ("¿qué significa el concepto #1006?"), Low o Medium alcanza y responde más rápido.
🧩 Ultracode — no es un modelo, es un modo
Ultracode se activa sobre Sonnet 5, Opus 4.8 o Fable 5 — no es una quinta opción de modelo. Reparte una tarea grande entre varios agentes que trabajan al mismo tiempo (uno busca bugs de cálculo, otro revisa consistencia de estilos entre archivos, otro verifica seguridad) y después cruza los resultados entre sí antes de mostrarte una conclusión. Es más lento que un pedido normal, pero mucho más exhaustivo.
Conviene usarlo cuando
  • Querés auditar todo el repositorio buscando bugs de cálculo o inconsistencias entre los distintos archivos HTML de payroll.
  • Estás migrando o actualizando algo que se repite en muchas páginas (un mismo componente, una misma librería).
  • Necesitás una revisión de seguridad antes de publicar un cambio importante.
  • Querés comparar varios enfoques de diseño para una misma pantalla antes de elegir uno.
No conviene usarlo para
  • Un fix puntual en un solo archivo.
  • Cambios chicos de texto, color o estilo.
  • Cualquier cosa que resolverías en un mensaje con Sonnet 5.
  • Preguntas rápidas sobre cómo funciona algo del código.
Cómo se activa: hay que pedirlo explícitamente — por ejemplo escribiendo "ultracode" en el pedido. No se activa solo, porque puede lanzar muchos agentes en paralelo y consumir bastantes más tokens que un pedido normal. Usalo cuando el volumen o el riesgo del trabajo lo justifique, no como costumbre.
Cómo pedir cambios en una app como las de este repo
1
Nombrá el archivo a tocar — por ejemplo "actualizá GestorNovedades_HyA.html". Claude Code lo abre, propone el cambio y te muestra el diff antes de guardar nada.
2
Para una página nueva, pedí que la genere completa en un solo archivo HTML autocontenido — como esta misma guía. Es el formato que ya usa el repo, no necesita build ni dependencias externas para funcionar.
3
Probá el resultado en el navegador antes de pedir el commit. Claude Code puede abrir la página y describir lo que ve, pero la validación visual final la hacés vos.
4
Si el cambio toca varios archivos a la vez (por ejemplo actualizar un mismo dato en todas las páginas), pedile primero que liste los archivos afectados antes de aplicar el cambio — o directamente activá Ultracode si son muchos.
5
Cerrá con un commit descriptivo. Claude Code lo prepara, pero (como en el aviso de arriba) la publicación final la coordina {{ reviewerName }}.
